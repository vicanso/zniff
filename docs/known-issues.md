# zniff 已知限制

P0 到 P3 里点名的能力已经接上。下面是仍然接受的缺口，不挡当前使用。

## 仍然不做

- HTTP/3、QUIC。UDP 不经过 HTTP 代理。
- Firefox 的证书库。Firefox 默认也不代理 localhost。验收浏览器是 Chrome、Safari、Edge。
- 透明代理、JSON 树、SQLite、cyberapi、Web 界面。
- 会话只在内存里。重启清空。单条 body 解压后最多 1 MB，整段会话最多 256 MB，超出丢掉最旧的未星标 flow。星标最多 32 条，不参与淘汰，因此星标集合可以让内存超过 256 MB。线字节和 WebSocket 消息文本不计入这两个上限。过滤写在 `config.toml` 的 `filter`，下次打开恢复。不再自动记下最近过滤词；要留住一套条件，用「保存」。顶栏「过滤」最底一行是已保存配置下拉选择、名称、「新建配置」和「保存」。「保存」把当前过滤、直通、规则、上游和三个开关写进 `saved_profiles`，最多 16 条。点一条一起恢复。添加规则写进当前规则，底栏仍停在名称框里的那条。「新建配置」清空当前这套并回到默认开关，不删已保存的条目。过滤、规则、直通、上游都空着时不保存。名称对得上当前这条、内容也没变时「保存」是灰的，有改动才可以点。旧的 `saved_filters` 和 `saved_rules` 在还没有 `saved_profiles` 时并进来。停半秒才写入，避免每敲一个字都改文件。

## 平台

- 系统代理默认关闭。只有「更多」里的「系统代理」为开时，开始抓包才会改系统代理。启动不会单独打开它。上次关闭时若正在抓包，下次打开会自动开始；系统代理开关若是开的，这次开始仍会改系统代理。按「停止」后 `capturing` 写回 false。
- Linux 非 GNOME：开了「系统代理」也改不了，界面给出监听地址，需要自己指到 `127.0.0.1:端口`。监听仍会起来。
- Windows 只改当前用户的 WinINET，不改 WinHTTP。
- macOS `security add-trusted-cert` 可能要用户点确认。`security find-certificate` 只说明证书在登录钥匙串里，不保证 SSL 信任策略已经生效。
- 带密码的系统代理：`networksetup` 读不回密码，停止后可能恢复不完整。
- Windows、Linux 上「移除证书」和「证书已安装」状态检测还没接上（`ca::remove` 直接报错，`ca::is_installed` 在非 macOS 下返回 `false`）。macOS 用 `security find-certificate` 与 `security delete-certificate`。
- 窗口位置和大小不记。nsh 0.4 的 `AppOptions` 仍只有初始 `size`，没有坐标。公开的窗口接口是 `set_title_bar`、`title_bar`、`close_window`。`window()` 只返回表面尺寸。`set_frame` 和 `desktop_command` 仍是 `pub(crate)`。`nsh-platform-macos` 重导出了 `objc2_app_kit`，应用拿不到 nsh 正在用的那扇 `NSWindow`；用 `NSApplication` 的窗口列表去猜，会和 nsh 自己的标题栏、全屏状态抢外框。多显示器 UUID、重叠面积，以及 Windows、Linux 的同一套恢复因此先不做。启动尺寸仍是 `app/src/main.rs` 里的 `(1200, 760)`。

## 代理行为

- 没配上游时，源站连接直连，不走系统代理。`config.toml` 里配了 `upstream_proxy`（`host:port`）后，明文用绝对形式，TLS 先对上游发 `CONNECT`。
- 明文 HTTP 省略 `Connection` 时补 `Connection: keep-alive`。body 读完、双方都没要求关闭、状态不是 101 时才放回池。同一个键最多 4 条，键超过 32 就清空。HTTP/1 的 TLS 不进这个池。重放强制 `Connection: close`，不进池。
- HTTP/2 在一条客户端连接上复用源站连接，另外缓存最多 16 条发送端。空闲超过 45 秒就丢掉这条缓存，连接驱动结束时也删掉这一代。这条浏览器连接发现连接已关、空闲过久或发送失败时，会换一条新的源站连接；请求还没送出时再送一次。已经写进连接的请求不重试。
- 源站 TLS 探测失败后会关掉那条探测连接，另开一条 TCP，再把缓冲的 ClientHello 放进去。探测失败的同一条 TCP 不能复用。
- 源站没选 ALPN 时按 HTTP/1.1 记。
- ServerHello 之前失败改成 TCP 隧道，只记目标和原因。源站 TLS 探测失败也改隧道转发，默认不在列表里记一行：这条连接没有解密出的 HTTP。配置弹出层里的「隧道失败」打开后才记，并写入 `config.toml` 的 `show_tunnel_failures`。连接源站超时、不是 TLS、直通名单仍记一行。ServerHello 之后的解析失败只记错误，不能退回隧道。
- 图片预览按原图像素画，小图不放大。宽或高超过 200 时等比缩小。
- ServerHello 之后客户端断开，界面记成「证书被拒绝」，并附一句猜测。收到 `unknown_ca` 一类告警时，猜客户端不信任 zniff CA。收到握手失败告警，或连接被重置且主机像 Google、Apple、Microsoft 这类常钉扎的名字时，猜是证书钉扎，建议加入直通名单。其余重置先让用户核对 CA 是否已信任。这仍不是钉扎的专用检测。
- 转发到源站失败时，错误仍以步骤名开头（例如「HTTP/2 上游」），后面附一句猜测。发送端报连接已取消、耗时接近 0 时，猜的是复用的 HTTP/2 连接已经关掉，下一次会重新连接。重置、拒绝连接、对端提前关闭、源站要求 HTTP/1.1、主机名解析失败和超时会换成对应的那一句。看不出具体原因时，只说明这一步失败了。这是按错误种类推断的，不是源站给出的原因。已经记下的旧行仍是当时写下的短句。
- HTTP/2 这一层只表示两边用源站选定的协议。不解析帧、HPACK、trailer、gRPC。
- 界面里非 UTF-8 body 只显示前 4 KB 十六进制，UTF-8 只显示前 256 KB，截在字符边界上。记录本身仍保留最多 1 MB。复制用的是记录原文。左栏按到达时间排列，最新在最下面；离底部不超过一行时跟着新流量，再往上翻就停在当前内容。响应 body 在内层已经 `is_end_stream()`，或 `RecordingBody` 被丢弃时记完成。空响应（例如 `304`）和最后一帧不会停在「进行中」。超过 1 秒的时间列用警告色。主机列保持正常颜色。没有状态码的失败行，路径列用错误色。
- WebSocket 从旁路解析帧并立刻转发。转发握手时去掉 `Sec-WebSocket-Extensions`，避免谈成 `permessage-deflate`。非法帧或仍然带扩展位（`RSV1 != 0`）只停止解析后续帧，不切断对拷。消息最多 200 条或 256 KB 文本。`Content-Type` 含 `event-stream` 且没有 WebSocket 消息时，按 SSE 事件列出。
- 规则里 `map-local`、`map-remote`、`break`、`break-res` 是终点，按写下来的顺序第一条命中。`delay`、`header`、`cors`、`replace` 不占这条名额，匹配到的都会叠加上去，包括写在终点后面的行。规则的域名段和 Path 前缀段均支持用 `|` 或 `,` 表示多个 OR（例如 `replace a.com|*.b.com/api|/v2 res ...`）。`replace 主机/路径 res 原文 -> 替换成` 改响应正文，`req` 改请求目标（path 和 query 连在一起）和请求正文。`原文` 不能有空格，`替换成` 可以有。目标改完仍须以 `/` 开头，否则这一处不改；没有 body 也会改目标。正文只处理带 `Content-Length` 且不超过 1 MB 的内容：先按 `Content-Encoding` 解开，改到文字再去掉压缩头发明文。对不上、不是 UTF-8、分块或超过 1 MB 时照原样转发。同一条又命中响应断点时，这一轮不替换，断点仍看源站正文。顶栏「过滤」弹出层右栏里的规则框是带行号的编辑器，右上角会提示语法有误的行号。下面可以通过 8 项分段标签（替换、转发、文件、延迟、断点、响应断点、改头、跨域）快速追加一行，支持分别填写多域名 OR 与多 Path 前缀 OR。域名和 Path 都可以留空，留空匹配全部。行右键「填入断点」写入 `break 主机路径`，查询串不放进去。改已有的哪一行仍没有单独的表单编辑器。`delay` 最长 30 秒。`map-local` 可写 `status=429`，省略时是 200。`header` 用 `req` 或 `res`，再写 `set` 或 `del`。`cors` 给响应补跨域头；`OPTIONS` 且没有终点规则时直接回 204，不拨源站。明文在拨号前应用，HTTPS 在源站连接打开后应用，WebSocket 和 `CONNECT` 跳过。Map Remote 换了主机就另开连接。请求断点和响应断点共用一个槽位，新命中会顶替并自动放行上一条，等 60 秒，超时当放行。响应断点先缓冲 body，最多 1 MB。已经写明的 `Content-Length` 超过 1 MB 时不暂停，记「响应断点跳过」后照常转发。分块或未知长度读过 1 MB 时，这条响应记失败。放行时可以改状态码、头和 body。重放不套规则和断点。规则里的文件路径不能有空格。顶栏「过滤」弹出层右栏顶部有「启用规则」和「启用断点」，默认都开，只在这次窗口里记住，不改规则文本，也不写入 `config.toml`。关掉规则后，Map、替换、延迟、头、CORS 和断点都不生效。只关掉断点时，其它规则仍生效，`break` 和 `break-res` 不再暂停。已经停住的那一条仍要等「放行」、丢弃或 60 秒超时。两个开关有一个关掉时，顶栏「过滤」按钮用警告色。
- 直通名单在 ClientHello 之后看 SNI，没有 SNI 就用 CONNECT 主机。支持空格、`,`、`;` 或 `|` 分隔多个域名 OR。`*.example.com` 匹配子域，不匹配顶点。`only:` 是白名单。`*` 全部直通。空名单全部解密。
- `GET` 或 `HEAD` 的路径去掉 query 后是 `/zniff-ca.crt` 时直接返回根证书 PEM。直接访问 `/`，或路径是 `/zniff`，返回手机安装页。`Accept-Language` 首段不是 `zh` 时安装页是英文，空的或 `zh` 仍是中文。代理请求里的 `http://其他主机/` 仍转发出去。
- 监听默认 `127.0.0.1:8877`。端口和局域网开关记在 `config.toml` 的 `listen_port`、`listen_all`，`0` 拒绝，绑不上就报错，不悄悄换端口。端口已被占用时说明多半是另一个 zniff 还在监听，并提示关掉它或改底栏端口。`listen_all` 打开后绑 `0.0.0.0`。监听地址是 `0.0.0.0` 之后，底栏「扫码」点开才显示安装页二维码。默认地址是访问公网的那张 IPv4；隧道和 `198.18.0.0/15` 让位给物理网卡。多张网卡可改选。没有系统文件选择框。图片预览只做 png、jpeg、webp、gif，且响应已结束、非空、未截断。SVG 不预览。

## 已接上，不再当作待办

这些有库测试：

- 清空会话。顶栏有「清空」按钮，「更多」的第一项也是「清空」，右侧是会话条数；「导出」是第二项。工具栏「更多」左边用同一数字。没有过滤词时只显示总数，有过滤词时显示「筛选数 / 总数」。清的是整个会话。清列表、字节和丢弃计数，不清下一条 id。切换选中行或点「清空」会收起「编辑重发」并清掉编辑框。
- 复制 URL、cURL、请求 body、响应 body。cURL 跳过 `Host` 和 `Content-Length`。非 UTF-8 复制十六进制。二进制请求 body 不写进 cURL。
- 记住监听端口。摘要里有开始时间、TTFB、总耗时、请求和响应线字节。时区用启动时的 `date +%z`，否则 UTC。HAR 导入按 `timings.wait`、`time` 和 `bodySize` 回填 `response_at`、`finished_at`、`request_bytes`、`response_bytes`。`bodySize` 缺失或为负时用已还原的 body 长度。
- JSON、表单、XML、HTML 默认美化，可切「原文」。`config.toml` 的 `default_pretty` 缺省为开；「更多」里「默认美化」关掉后下次启动用原文，并马上按新模式重画当前选中的详情。卡片上的「美化 / 原文」仍只改当前窗口。复制和另存仍用记录原文。查询参数单独成表。美化时 `x-www-form-urlencoded` 的请求 body 也按键值行画，值下面带 JWT、时间戳和 Base64 提示；原文仍是整段。另存写到下载目录的 `zniff` 文件夹（Linux 读 `~/.config/user-dirs.dirs` 的 `XDG_DOWNLOAD_DIR`，否则 `~/Downloads`），状态栏给出完整路径。HAR 仍导出到数据目录的 `exports/`。
- 过滤是 AND 词，同一个词内支持 `|` 或 `,` 表示 OR：`host:` / `domain:`（支持 `*.` 通配符与多域名 OR）、`path:`（支持多 Path 前缀 OR）、方法精确、状态精确或 `1xx`–`5xx`、`失败`、`type:` / `ct:`、`body:`、`header:`、`pin:`、`slow:`、`mute:` 或 `-词`，其余匹配主机或路径。`body:` 搜请求和响应 body，`header:` 搜头名和头值。`pin:` 只留星标。`slow:` 只留从开始到结束不少于 1 秒的流量；还没结束的用现在的时间，和列表警告色是同一条规则。`mute:` 和 `-词` 排除主机或路径里带这个词的行。顶栏「过滤」双栏面板左侧有域名 OR、Path 前缀 OR、排除域名/路径 OR 三个结构化输入框（与完整过滤表达式双向同步），以及 JSON、报错、星标、慢请求四个快捷筛选开关。点一下追加整词 `type:json`、`失败`、`pin:`、`slow:`，再点去掉。已经写了 `ct:json` 或 `fail` 时，对应开关也算打开，再点会把这些别名一起去掉。列表右键或详情「更多」里的「只看」会把当前主机并入 `host:` OR 列表，「屏蔽」会把当前主机并入 `mute:` OR 列表。复制、另存、星标、基准、重放、编辑重发和美化也在这个菜单里。
- 「编辑重发」可改方法、URL、头和 body。URL 框以 `curl` 开头时，按 `-X`、`-H`、`--url`、`-d` / `--data*`、`-A`、`-e`、`-b` 填进这些框；带 body 又没写方法时当成 `POST`。发送时按新 body 重算 `Content-Length`。URL 改了就丢掉旧的 `Host`。停在响应断点上再点「编辑重发」，改的是状态码、响应头和响应 body，由断点条的「放行」送出。状态码只接受 100–599。
- 复制还有 `fetch`、Python `requests`，以及响应 JSON 对象或数组的浅层 TypeScript `interface`。「更多」里「复制代理环境」复制 `http_proxy`、`https_proxy`、`SSL_CERT_FILE`、`NODE_EXTRA_CA_CERTS`、`REQUESTS_CA_BUNDLE`、`CURL_CA_BUNDLE`、`GIT_SSL_CAINFO`，证书路径指向数据目录的 `ca.crt`，端口用当前记住的监听端口。请求头和查询值里能认出的 JWT、10 位或 13 位时间戳、可打印 Base64 会附在原值下面。两条流量可以用「基准」做行级对比。设为基准的那一行，方法列最前有一条红竖线，和选中时的蓝线同一位置；这一行如果正在被选中，仍显示蓝线。对比卡片顶部用同一红色标「基准」、用绿色标「当前」：红的是基准，绿的是当前选中。再点这条的「基准」会取消，菜单写成「取消基准」，红线和对比卡片一起去掉。换一条再点「基准」会改成新的。超过 1 秒的时间列用警告色。星标在方法徽章前有蓝点，藏起主机列也看得到。
- 直通名单、上游绝对形式、明文连接池、WebSocket 文本帧、握手去掉 `Sec-WebSocket-Extensions`、Map Local、断点丢弃、HTTPS 上的 Map Local / Map Remote / 断点放行、HTTP/2 发送端缓存命中、空闲过期后重连、同一条客户端连接上换源站连接、HTTP/2 Map Local、HTTP/2 断点丢弃、重放改方法 URL 头和 body、`/zniff-ca.crt`、安装页 `/zniff` 有代理往返测试。HAR、规则语法、SSE、美化、`body:` / `header:`、`status=` / `delay` / `header` / `cors`、响应断点改写、星标不淘汰、环境变量、`fetch` / Python / TypeScript、cURL 解析、JWT 提示和行级 diff 有单元测试。

## 界面

左栏默认宽 560，可拖到 280–1100。方法、状态、路径、间隔、耗时、主机、协议、大小、URL、头和 body 用等宽。按钮和句子用界面字体。英文界面的按钮和说明不改成等宽。

- 左栏顶部只保留过滤搜索框（有内容时带 `×` 一键清空按钮）和右侧的列显隐图标。完整的流量过滤与规则代理配置收纳在顶栏「过滤」双栏面板里，按钮右侧显示当前生效的规则条数。
- `↑` / `↓` 在当前筛选后的列表里换选中行。没有选中时 `↓` 选第一条，`↑` 选最后一条，到头就停住。选中的 id 已经不在筛选结果里时，按同样的规则重新选。换行会收起「编辑重发」。过滤框或其它输入框有焦点时，方向键仍移动光标。`Cmd/Ctrl+K` 清空整个会话，和「更多」里的「清空」一样。`Cmd/Ctrl+F` 聚焦过滤框。`Cmd/Ctrl+R` 重放当前选中行，没有选中时状态栏提示需要选择。`make dev` 的热重载可能吃掉 `Cmd+R`。方向键不滚动列表。
- 列表默认列是方法、路径、状态、间隔、耗时、主机。方法列始终在最左，路径紧跟其后。这两列固定在左侧，横向滚动时不离开。状态、协议、间隔、耗时、主机、大小在它们右边，可以横向滚走。每一列的右缘可以拖，宽度记在 `column_widths`，下次打开还在。路径默认 240。过滤胶囊行右侧的列图标和表头右键都能按表格列顺序开关路径、状态、协议、间隔、耗时、主机、大小，写进 `config.toml`：`show_status`、`show_path`、`show_gap`、`show_elapsed`、`show_host` 默认开，`show_protocol`、`show_size` 默认关。旧文件没有这些键时仍是现在这几列。间隔是距当前列表里上一条的时间，首条 `+0 ms`（`+45 ms`、`+1.24 s`，再长用分和小时）。过滤之后按看得见的行重算，被滤掉的行不计入。悬停显示本地 `HH:MM:SS.mmm`。详情摘要用同一绝对时间。耗时列是这条请求从开始到收完响应，和详情里的「耗时」同一段，还没结束是 `—`，不少于 1 秒用警告色。写在 `show_elapsed`，缺这一项就显示。藏起一列后，它不占宽。主机默认 120。显隐不靠表格自己的开关，只把要显示的列交给它。列设置菜单底部可切换路径列显示「仅路径」或「完整 URL」（`show_full_url`，默认 false，开启时列标题变为 `URL` 且显示 `flow.url`），以及路径和主机超出时的省略位置（`ellipsize`：`head` 开头、`middle` 中间、`tail` 结尾，默认 `middle`），悬停显示全文。协议列用和摘要徽章相同的名字，大小列是响应的线字节。详情摘要在协议徽章旁边显示这条流量实际命中的规则名，例如 `delay replace break`。没有命中就不显示。左栏与右栏之间可拖，松开后把宽度记到 `list_width`，限制在 280 到 1100（同时随当前窗口宽度实时约束上限为 `window_w - 340`），默认 560。顶栏「过滤」弹出层宽度随窗口宽度在 680–1080 自适应，规则编辑器高度随窗口高度在 105–360 自适应。分割条宽 6，悬停时中间的线变宽并改成强调色。
- 没有状态码的失败行，列表状态是 `ERR`，路径用错误色显示记录里的原因。转发失败的原因是步骤名加一句猜测。窗口会翻译一批固定原因，原文仍是写入时的语言。进行中、还没有错误的行状态是 `—`。过滤仍用记录里的真实路径。详情摘要在没有状态码且有错误时徽章是 `ERR`，否则仍是「等待响应」。
- 详情在摘要之后是响应 body、响应头、请求 body（有正文、表单或说明才画）、查询参数、请求头，然后是行级对比和消息。查询、对比、消息、两张 body 和两张头卡片可以点标题折叠，摘要不折叠。这些标题都在卡片顶栏里，左内边距相同。折叠只在这次窗口里记住，不写入配置，换选中行也不重置。请求 body 为空且没有截断或解压说明时不画那张卡片。响应 body 没有正文、没有说明、美化模式下也没有图片时同样不画。图片在美化时按比例画进响应 body 卡片的预览框，不裁切铺满，并写上字节数；这时去掉「十六进制只显示前 N 字节」这句，解压失败等其它说明仍留下。原文显示十六进制，默认每 16 字节一行，这块区域摆开后宽度够 32 字节时改成一行 32 字节，两组 16 字节之间多一个空格；行首是 `0001` 这种四位行号；复制仍是不带行号、每 16 字节一行的记录。并保留那句截断说明。JSON、HTML、XML，以及不少于 80 字节的多行文本，画在只读 `editor` 里，带行号和折叠。请求和响应 body 按行数撑开，一行高 18，最多 10 行，再多在卡片里滚动。短文本和十六进制同样不超过 10 行。没有 `Content-Type` 或标成 `text/plain`、但正文以 `{` 或 `[` 开头的，也按 JSON 高亮。短文本和十六进制仍是普通等宽文本。「编辑重发」的头和 body 用可编辑的 `editor`。有基准时，对比卡片用 `diff_view` 的上下对照，两边是 URL、请求头、请求 body、响应头、响应 body。两张 body 卡片的标题上都有「美化 / 原文」，点标题不会切到美化。菜单里仍可切换。美化时 `Cookie` 和 `Set-Cookie` 按 `;` 拆开，每个键一行，名字是 `Cookie · session` 这种；没有等号的属性（`HttpOnly`、`Secure`）值留空。原文和复制仍是整段。美化时请求头和响应头按名字忽略大小写升序，同名保持原来的先后和大小写；原文、cURL 和复制不排序。
- HAR 导出仍写到数据目录的 `exports/`。过滤框有内容时只导出当前匹配的流量，「更多」里「导出」右侧是将写出的条数；过滤框空着仍导出整个会话，这时不显示条数。「导出 HTML」按同样的过滤写成一份不刷新的页面，也在 `exports/`。「分享 15 分钟 / 1 小时 / 8 小时」生成 UUID，地址是 `http://{地址}:{端口}/s/{uuid}`，页面每 2 秒按分享当时过滤框里的条件看会话，之后改过滤框不会改这条链接。过滤框空着就是整个会话。同时只有一条链接，停抓包或「停止分享」后失效。没开局域网时只在本机。分享请求不记入会话。分享页每条正文最多 16 KB，最多 400 条较新的记录。导入在顶栏「更多」里，路径空着就读数据目录的 `import.har`，把 `.har` 拖到窗口上也会导入。没有系统文件选择框。

## 后续吸引力增强方向（这一轮跳过）

上面第 1 到第 4 组里，环境变量、响应断点、状态码和延迟、头改写、CORS、行级对比、只看 / 屏蔽 / 星标、慢请求在时间列着色、JWT 与编码提示、`fetch` / Python / TypeScript、粘贴 cURL，都已经接上。下面这些不做：

- **TCP 建连和 TLS 握手分段计时**。连接池命中时没有新的握手。摘要里已经有 TTFB 和总耗时。慢请求用时间列上超过 1 秒的警告色代替分段计时。
- **丢包和带宽限制**。`delay`（最长 30 秒）和 `status=` 覆盖 Loading、超时和错误边界。按字节限速或随机丢包是另一套转发，不放进现在的规则。
- **JSON 树对比**。对比是 URL、请求头、请求 body、响应头、响应 body 的行级差异，每边最多 200 行。不做可折叠的 JSON 树。
- **超过 1 MB 的响应改写**。响应断点的缓冲上限就是单条 body 上限。更大的响应只转发，不在界面里改。
- **完整 cURL 语法**。不解析换行续行、`-G`、`--json`、`--form` 和多段 body。认不出的旗标忽略。
- **非 JSON 的 TypeScript**。响应不是 JSON 对象或数组时，「类型」提示不可用，不猜表单或 XML。
- **正则表达式（Regex）过滤与正则替换**。当前多域名 OR（`host:a.com|*.b.com`）与多 Path 前缀 OR（`path:/v1|/auth`）已覆盖绝大多数多服务联调场景；引入正则会带来转义负担与全量流量匹配开销，暂不引入。
- **单条规则独立开关与拖拽排序**。规则框保持纯文本一行一条（支持 `#` 注释禁用某一行），并配有顶部「启用规则 / 启用断点」总开关与实时语法行号校验，暂不拆成复杂的表格行编辑器。
- **跨 Path 前缀的笛卡尔积之外的独立规则绑定**。一条规则里的 `a.com|b.com/v1|/v2` 对列出的所有域名统一匹配列出的所有 Path 前缀；若不同域名需要完全不同的 Path 前缀，直接分写两行规则即可。
- **独立的 `jsAppend://` 网页脚本注入协议语法**。类似 Whistle `baidu.com jsAppend://baidu.com/sdk.js` 的网页脚本注入需求，直接用现有 `replace baidu.com res </body> -> <script src="https://baidu.com/sdk.js"></script></body>`（或替换 `</head>`）即可覆盖，支持多域名/多 Path 前缀 OR；不单独引入 `jsAppend://` 语法，以免为了追加脚本而将所有分块编码（Chunked）响应强行缓冲，或误伤同域名下的 JSON/JS 等非 HTML 响应。

### 二、既有文档中尚未接上或受限的事项汇总

除上述待实现增强外，现有代码与文档中保留的未完成项及平台限制汇总如下：

1. **Windows / Linux 证书状态检测与卸载尚未接上**：`app/src/ca.rs` 中仅实现了安装（Windows `certutil -user -addstore Root`、Linux NSS `certutil -A`），`ca::remove` 在 Windows 与 Linux 上仍直接报错返回，`ca::is_installed` 在非 macOS 下固定返回 `false`。
2. **窗口位置与尺寸记忆恢复未接入**：受限于 `nsh 0.4` 的 `AppOptions` 仅提供初始 `size`、未暴露窗口坐标及跨平台 `set_frame` 接口，暂不持久化窗口位置与大小，每次启动尺寸固定为 `(1200, 760)`。
3. **已有规则行无独立表单回填编辑**：过滤面板右栏底部的 8 项分段标签用于快速追加新规则行，修改已有规则仍直接在上方带行号与语法校验的纯文本编辑器中编辑。
4. **规则语法的空格限制**：规则文本按空白字符分词，因此 `map-local` 的本地文件路径不能包含空格，`replace` 的匹配原文不能包含空格（替换目标文本可以包含空格）。
5. **无系统原生文件选择框**：HAR/HTML 导出固定写入数据目录 `exports/`，另存响应固定写入下载目录 `zniff/`，HAR 导入默认读取数据目录 `import.har` 或通过拖拽文件到窗口触发。
6. **各平台系统代理能力边界**：
   - Linux 非 GNOME 环境无统一系统代理设置接口，开启「系统代理」后仅启动监听并在状态栏提示手动指向 `127.0.0.1:端口`。
   - Windows 仅修改当前用户的 WinINET 注册表项，不修改 WinHTTP。
   - macOS 带密码认证的系统代理无法通过 `networksetup` 读回密码，停止抓包后密码项无法自动还原；`security find-certificate` 仅能确认证书存在于登录钥匙串，无法直接判定 SSL 信任策略是否已被用户勾选生效。
